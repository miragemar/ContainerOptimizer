## 🚀 How to Use ContainerOptimizer

ContainerOptimizer — це локальний CLI/TUI-застосунок для аналізу проєктів, AI-генерації Dockerfile та перевірки Dockerfile за базовими правилами безпеки.

### 1. Запуск застосунку

Відкрий WSL Debian і перейди до каталогу проєкту:

```bash
cd ~/ContainerOptimizer
```

Активуй віртуальне середовище, якщо воно ще не активне:

```bash
source .venv/bin/activate
```

Запусти термінальний інтерфейс:

```bash
containeroptimizer-ui
```

Після запуску використовуй доступні дії в інтерфейсі.

### 2. Analyze — аналіз проєкту

**Призначення:** дослідити структуру проєкту перед контейнеризацією.

1. Вибери `Analyze`.
2. Введи абсолютний шлях до каталогу проєкту.
3. Переглянь результати аналізу.

Аналізатор визначає:
- мови та технологічні стеки;
- файли залежностей;
- можливі точки входу;
- Python CLI-команди, оголошені в `pyproject.toml`;
- наявність Dockerfile, `.dockerignore` і Docker Compose.

**Приклад шляху для тестування:**

```text
/tmp/containeroptimizer-demo
```

Приклад очікуваного результату: визначений Python-стек, знайдений `pyproject.toml` та CLI-команда `demo-greeter`.

### 3. Generate Dockerfile — генерація Dockerfile

**Призначення:** створити Dockerfile на основі метаданих проєкту за допомогою Gemini API.

1. Вибери `Generate Dockerfile`.
2. Введи шлях до каталогу проєкту.
3. Дочекайся відповіді Gemini.
4. Перевір створений Dockerfile перед використанням.

Для роботи потрібні:
- налаштований `GEMINI_API_KEY`;
- доступ до Gemini API;
- доступна модель і відповідна квота.

API-ключ зберігай у локальному `.env`. Не додавай цей файл до Git.

AI-генерація може завершитися помилкою або тайм-аутом. Згенерований Dockerfile необхідно перевірити: успішна генерація ще не гарантує, що образ збереться або контейнер працюватиме.

### 4. Security Audit — перевірка безпеки

**Призначення:** знайти потенційні проблеми в Dockerfile.

1. Вибери `Security Audit`.
2. Вкажи шлях до Dockerfile, який потрібно перевірити.
3. Переглянь знайдені проблеми та рекомендації.

Поточні евристичні правила перевіряють:
- `CO001` — відсутність `FROM`;
- `CO002` — використання тегу `:latest`;
- `CO003` — відсутність `USER`;
- `CO004` — використання `ADD`;
- `CO005` — можливу проблему з очищенням кешу `apt`;
- `CO006` — відсутність `HEALTHCHECK`.

Це базові перевірки, а не повний аудит безпеки контейнера. Не всі правила застосовні до кожного образу, тому результати потрібно інтерпретувати в контексті проєкту.

### 5. Перевірка Dockerfile через Docker

Після генерації та аудиту перевір файл вручну.

Перейди до каталогу тестового проєкту:

```bash
cd /tmp/containeroptimizer-demo
```

Переконайся, що Dockerfile існує, і переглянь його:

```bash
ls -la
cat Dockerfile.generated
```

Якщо файл створено в іншому місці, використовуй фактичний шлях, який показав застосунок.

Перш ніж збирати образ, перевір базовий образ, копіювання файлів, встановлення залежностей і команду запуску. Потім можна виконати Docker build та перевірити роботу контейнера.

### 6. Використання CLI без TUI

Застосунок також має CLI-команди:

```bash
containeroptimizer analyze /path/to/project
containeroptimizer generate /path/to/project --output Dockerfile.generated
containeroptimizer audit /path/to/Dockerfile
```

Перед генерацією перевір доступні аргументи командою `--help`. Для генерації у вже наявний файл потрібно враховувати захист від перезапису.
